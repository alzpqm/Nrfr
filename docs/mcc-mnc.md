# MCC／MNC 與代碼還原

SIM 電信業者代碼由 3 位 MCC 與 2／3 位 MNC 組成，以字串處理，保留前導零。

## 目前功能範圍

**1.1.4 候選版暫停新的 MCC／MNC 套用**。Android 使用 SIM 代碼及業者條件篩選 APN；覆寫代碼可能讓原 APN 消失、新建項目無法保存或選取。1.1.3 的相容項目方案已撤回，目前未確認可靠的免 root 替代方法。

可繼續調整國家碼及名稱、查閱業者預設代碼，或還原舊版修改。選擇預設業者不會套用 MCC／MNC。

| 資料來源 | 目前處理 |
| --- | --- |
| SIM 代碼 `TelephonyManager.getSimOperator()` | 顯示；還原時核對原值 |
| 訂閱資料 `SubscriptionInfo.mccString/mncString` | 顯示；本機備份缺失時作為還原候選來源 |
| 連線網路 `TelephonyManager.getNetworkOperator()` | 僅顯示 |
| 基地台、IMSI、ICCID、實體 SIM 內容 | 不修改 |
| 其他 App 的快取、帳號或伺服器地區 | 不保證改變 |

## 還原流程

1. 選擇原來修改的 SIM，點選「還原設定」。
2. App 嘗試回復本機備份中的代碼與名稱，並清除該 SIM 的 CarrierConfig 覆寫。APN 權限與查詢不參與這一步。
3. 回讀原 SIM 代碼；不一致時保留備份，顯示尚未確認還原。代碼與國家碼／名稱的部分失敗會分別說明。
4. 若有 1.1.3 的本機 APN 回復紀錄，再委派 APN 權限，清理可確認未被修改的相容項目。清理失敗會另列提示，不阻止原代碼回復。
5. 按提示重新啟動手機，重新啟動 Shizuku，核對原代碼、APN 保存及選取、行動數據，再執行還原以重試未完成的清理。

系統未提供完整清除介面時，App 先回復代碼與備份名稱，再提示重新啟動手機結束測試覆寫狀態。備份缺失時只採用有效的訂閱資料代碼，不把目前可能已被覆寫的 SIM 代碼當作原值；無法取得可靠候選值時，不宣稱代碼已還原。

本機備份紀錄的是首次修改時讀到的值；若當時已有其他工具的覆寫，重新啟動手機後仍須核對實際 SIM 原值。

## 舊相容 APN

清理只針對本機回復紀錄與所選 SIM 匹配的項目。刪除前核對 ID、名稱與完整參數雜湊；被修改或無法辨識的項目會保留。原 APN 不被改寫，不建立新的相容項目，也不清空 APN 選取。

若目前已選取原 APN，保留該選取；若仍選取相容 APN，嘗試回到其對應的原項目。APN 清單未就緒或沒有可確認的原項目時，保留回復紀錄供重試。

解除安裝會失去本機紀錄，系統資料庫內的相容項目不會自動移除。沒有紀錄時不以名稱猜測並刪除項目。

## 資料保存

原代碼備份以 SIM 識別碼的雜湊綁定；APN 回復紀錄只保存項目 ID、名稱與雜湊，均留在本機，排除雲端備份及裝置移轉。App 不上傳這些資料，也不記錄 APN 帳號、密碼或 Provider 的原始錯誤參數。

1.1.3 建立的系統 APN 可能含 SIM 匹配資訊；分享系統 APN 截圖或紀錄前，請遮蔽 SIM 識別資訊、帳號與密碼。

## 業者預設

提供 177 組不重複代碼、45 個國家／地區，可搜尋名稱、地區或代碼。預設包含常見、歷史及相容用途代碼，不是全球現行業者名錄，應以各地主管機關公布的分配為準。

參考：[Android TelephonyManager](https://developer.android.com/reference/android/telephony/TelephonyManager)、[ITU E.212](https://www.itu.int/rec/T-REC-E.212)。
