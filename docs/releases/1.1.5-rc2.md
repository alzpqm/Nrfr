# Nrfr 1.1.5-rc2 — 既有目標 APN 匹配衝突候選版

本機已沿用既有 S25 測試簽章，覆蓋安裝 `com.github.nrfr.s25`，版本
`1.1.5-rc2-s25`、versionCode 13。GitHub Release 尚未建立，原 1.1.4 保留。

## 使用者回報與修改

rc1 會在「目標代碼已存在匹配的 MVNO APN」時套用失敗。真機快照確認原 4 筆
APN 未被刪除，但三星優先選到目標代碼下一筆 IMSI 型 MVNO，把原 APN 與原選取
排除在數據清單外。IMSI 參數仍為 null；這不是 IMSI 修改或 APN 權限空清單。

rc2 在修改代碼前，先將目標列的原匹配條件寫入 Nightzuku 持久還原紀錄，再暫時
改成逐列不重複、且經電話服務核對不匹配的 ICCID 條件。保留 ID、numeric、
連線欄位及既有項目，不複製或刪除它們，保留原本的精確 filtered／Settings／選取
比對。另一卡正在使用這些列時拒絕操作。

還原在原代碼恢復後逐列處理匹配條件；正向與反向均檢查完整唯一鍵，避免替換
其他項目。使用者後續連線編輯及軟刪除狀態會保留，不重建已刪除項目。

## 已完成的真機驗證

S25、Android 17／One UI 9、Nightzuku，免 root、無重啟：

- 使用實際失敗的目標預設，確實勾選修改 SIM 代碼；原預設數據卡不變時可套用。
  原 4 筆數據／畫面 APN 與選取 ID 保留，目標 7 筆既有 APN 僅兩個匹配欄位變更。
- 另一卡完整原 APN／選取未變，該卡指定行動網路的 DNS／HTTPS 204 通過。
- 新增 APN 可儲存顯示。清除候選版資料、正常重開後，三份還原紀錄逐字恢復，
  未手動匯入；再次儲存不同 APN 值可顯示。重複唯一鍵被攔下，未覆蓋原項目。
- 暫選 SIM1 數據後，指定 SIM 的行動 Network DNS／HTTPS 204 通過；刪除兩筆測試
  APN、行動數據關閉再開啟後，新 Network handle 再次通過，排除 Wi-Fi 與另一卡。
- 無重啟還原後，兩卡原代碼、完整原 APN／選取，及目標 7 筆既有 APN 的全部欄位，
  均符合測試前。本次專用規則與三組還原紀錄已清除，維護服務停止。
- 原預設數據卡、兩卡國家碼／名稱、螢幕逾時、USB 亮屏與注音輸入模式已恢復，
  原數據卡的指定網路 DNS／HTTPS 204 通過；安裝 APK 與簽署候選檔雜湊一致。
- 75 項單元測試、Lint、Android 與前端 CI 通過。

這些證據不涵蓋全部 APN 重設、外部同時修改、長期穩定性或其他系統組合。
清除資料後仍須正常開啟 Nrfr 並確認 Nightzuku 可用，才能維護後續新 APN。
原始診斷與私鑰只保留在本機；[調查紀錄](../s25-apn-investigation.md)只列去識別摘要。
